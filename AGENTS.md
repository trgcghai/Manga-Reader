# Repository Guidelines

## Layout

- `backend/` is a NestJS + TypeScript API. `backend/src/main.ts` is the entrypoint.
- `frontend/` is a TanStack Start + Vite + React app. `frontend/src/routes/__root.tsx` is the root route and `frontend/src/routes/index.tsx` is the home page.
- `frontend/src/routeTree.gen.ts` is generated by `npm run generate-routes`; do not hand-edit it.
- `docker-compose.yml` at the repo root is the local full-stack entrypoint.
- `opencode.json` at the repo root loads the Superpowers plugin for this workspace.
- `overview.md` describes the intended manga library format and offline-only product scope.

## Commands

- Backend: `cd backend && npm run start:dev`, `npm run build`, `npm run test`, `npm run test:e2e`, `npm run lint`, `npm run format`.
- Frontend: `cd frontend && npm run dev`, `npm run generate-routes`, `npm run build`, `npm run test`, `npm run lint`, `npm run format`, `npm run check`.
- Full stack: `docker compose up --build`.
- Docker dev uses bind mounts plus polling for watch mode; file edits should reload without restarting Compose.

## Workflow Notes

- Keep the app local-only: no auth, telemetry, cloud sync, or internet-backed dependencies unless the product scope changes.
- The backend is still a starter Nest app; the compose file provides Redis, MongoDB, and Postgres for future wiring, but the app code does not yet use them.
- User manga files should stay outside the repo; do not write into library folders unless a metadata workflow explicitly requires it.
- Prefer small fixture-based tests for file discovery, metadata parsing, translator/language selection, and reader progress.
