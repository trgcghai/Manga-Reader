# MR98: Parse Chapter Title from Filename

## Title
Extract chapter title from filename and display in batch import table.

## Description
Currently `parseChapterNumberFromFilename` extracts only the chapter number. The batch import dialog's Title column always shows `—`. Files often follow the pattern `chapter 001 - The Title.zip`. We need to extract that title part and display it in the batch import preview table.

Instead of adding a separate utility, rename and extend the existing function to return both chapter number and title.

## Requirement
- Rename `parseChapterNumberFromFilename` → `parseChapterInfoFromFilename`
- Change return type from `number | null` to `{ chapterNumber: number | null, title: string | null }`
- Update all callers (BatchImportDialog import + usage)
- Update the existing spec file to cover title parsing and rename test descriptions
- Populate the Title column in the data table with the parsed title (fallback to `—` if null/empty)

## Acceptance Criteria
- [ ] `parseChapterInfoFromFilename` returns `{ chapterNumber, title }` instead of just a number
- [ ] Pattern `chapter 001 - The Beginning.zip` → `{ chapterNumber: 1, title: "The Beginning" }`
- [ ] Pattern `ch 12 - A New Chapter.zip` → `{ chapterNumber: 12, title: "A New Chapter" }`
- [ ] Pattern `chapter05.zip` (no title) → `{ chapterNumber: 5, title: null }`
- [ ] Pattern `chapter 1 -   Extra Spaces  .zip` → title trimmed: `{ chapterNumber: 1, title: "Extra Spaces" }`
- [ ] Pattern `random.zip` (unparseable) → `{ chapterNumber: null, title: null }`
- [ ] Batch import table Title column shows parsed title, not `—`, for files with titles
- [ ] Files without parsed title still show `—` in Title column
- [ ] All tests pass (existing + new title tests)
- [ ] Frontend build succeeds (`npm run build`)
