# MR91: Backend import chapters and translations service

## Title

Create `ImportChapterService` for bulk creation of chapters and translations from Excel + ZIP.

## Description

Build the core import service that reads parsed Excel rows (from MR90's ZIP utility), resolves referenced entities, uploads files to MinIO, and creates chapters/translations via `ChapterService.create()`. This follows the same pattern as the existing `ImportMangaService`.

### Excel column schema

| Column | Required | Description |
|--------|----------|-------------|
| `MangaId` | Yes | Numeric ID of the parent manga |
| `Number` | Yes | Chapter number (decimal, e.g. 1, 1.5, 2) |
| `Title` | No | Chapter title |
| `Language` | Yes | Language name or code to resolve (e.g. "English" or "en") |
| `Translator` | Yes | Translator name to resolve |
| `File` | Yes | Relative file path within the ZIP (e.g. `files/ch01/en.cbz`) |

### Service logic

For each row (in order):

1. **Validate manga**: Look up `Manga` by `MangaId`. If not found → skip row with error.
2. **Resolve language**: Search `Language` entity by name (case-insensitive), then by code if name fails. If not found → skip row with error.
3. **Resolve translator**: Search `Translator` entity by name (case-insensitive). If not found → skip row with error.
4. **Read file**: Call `readFile(filePath)` from the ZIP utility. If `null` → skip row with error.
5. **Upload to MinIO**: Call `FileService.upload()` with the file buffer and appropriate mimetype (for CBZ: `application/zip`). Get back `{ key, url }`.
6. **Create chapter/translation**: Call `ChapterService.create(mangaId, dto)` with the resolved `number`, `title`, `languageId`, `translatorId`, and MinIO `url`.
7. **Collect results**: Count successes, collect per-row errors with messages.

### Error handling

- Each row is processed independently — one failing row does not stop the import
- Errors are collected as `Array<{ row: number; message: string }>`
- Common errors: manga not found, language/translator not found, file missing in ZIP, MinIO upload failure, duplicate chapter+language+translator conflict
- Return `ImportResult` with `total`, `created`, `errors[]`

### Implementation

- Create `backend/src/modules/manga/services/import-chapter.service.ts`
- Inject: `MangaRepository`, `LanguageRepository`, `TranslatorRepository`, `FileService`, `ChapterService`
- Method signature:
  ```typescript
  async import(
    mangaIdPrefix: number | null,  // optional prefix for mangaId in Excel rows
    rows: Record<string, string>[],
    readFile: (path: string) => Buffer | null,
  ): Promise<ImportResult>
  ```
- Reuse the existing `ImportResult` interface (already exported from `import-manga.service.ts`)
- Move `ImportResult` to a shared location if both services need it, or export independently

### Rows processed in transaction?

- No — each row is processed independently outside a global transaction
- The `ChapterService.create()` method itself handles its own uniqueness checks and database writes
