# MR93: Backend unit tests for import chapters service

## Title

Add unit tests for `ImportChapterService` and ZIP extraction utility.

## Description

Write comprehensive unit tests for the new bulk import components, following the same testing patterns as the existing `import-manga.service.spec.ts`. The tests should cover both the ZIP extraction utility and the import service.

### Test structure

Create two test files:
1. `backend/src/modules/manga/utils/zip-extractor.util.spec.ts` — tests for the ZIP extraction utility
2. `backend/src/modules/manga/services/import-chapter.service.spec.ts` — tests for the import service

### ZIP extractor tests

- **Happy path**: ZIP with a valid Excel file and organized CBZ files → returns correct rows and file buffers
- **Missing Excel**: ZIP without any `.xlsx` file → throws `BadRequestException`
- **Corrupted ZIP**: Invalid buffer → throws `BadRequestException`
- **File not found**: `readFile()` returns `null` for non-existent paths
- **Cleanup**: `cleanup()` removes the temp directory
- **Multiple sheets**: Excel with multiple sheets → only first sheet is parsed
- **Empty rows**: Excel with only headers, no data rows → returns empty array
- **Extracted file content**: `readFile()` returns the correct buffer matching the original file

### Import service tests

- **Happy path**: Valid rows with resolvable manga/language/translator → all rows processed successfully, `created === total`
- **Manga not found**: Row with non-existent mangaId → per-row error, other rows succeed
- **Language not found**: Row with unresolvable language → per-row error
- **Translator not found**: Row with unresolvable translator → per-row error
- **File missing in ZIP**: Row with file path that `readFile()` returns null for → per-row error
- **Mixed success/failure**: Multiple rows, some valid and some invalid → `created` and `errors[]` both populated correctly
- **Duplicate chapter**: Row that conflicts with existing chapter+language+translator → per-row error from `ChapterService.create()`
- **Empty input**: Empty rows array → `total: 0, created: 0, errors: []`
- **Language resolution fallback**: Language resolved by code when name fails
- **Translator case-insensitive**: Translator name matched case-insensitively

### Test fixtures

- Create fixture ZIP files using `adm-zip` programmatically in `beforeEach`
- Create fixture Excel files with `XLSX` programmatically
- Mock `MangaRepository`, `LanguageRepository`, `TranslatorRepository`, `FileService`, `ChapterService`
- For language lookup, mock both the name-based and code-based queries

### Changes needed

1. Create `backend/src/modules/manga/utils/zip-extractor.util.spec.ts`
2. Create `backend/src/modules/manga/services/import-chapter.service.spec.ts`
3. Add programmatic fixture generation for ZIP and Excel files
4. Cover all test cases listed above
5. Ensure all tests pass with `cd backend && npm run test`

## Requirement

- Tests use NestJS testing utilities (`Test.createTestingModule`) for service tests
