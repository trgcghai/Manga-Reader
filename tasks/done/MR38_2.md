# MR38: Move Chapter into Manga Module

## Title
Consolidate Chapter entity and logic into the Manga module.

## Description
The Chapter module currently exists as a standalone module with its own controller, service, entities, and module registration. Since chapters are inherently part of a manga (a chapter cannot exist without a manga), the chapter module should be collapsed into the manga module. This removes unnecessary module boundaries and simplifies the architecture.

## Requirements
- Remove `ChapterModule`, `ChapterController`, and `ChapterService`
- Move chapter-related entities (`Chapter`, `Translation`, `Page`) into the manga module's `entities/` directory
- Update the `MangaModule` to register the moved entities via `TypeOrmModule.forFeature()`
- Remove the chapter entity scan endpoint (likely `GET /chapters` or similar) and its associated test
- Update any cross-module imports to reference the new entity locations
- Ensure the manga module's existing functionality remains intact

## Acceptance Criteria
- [ ] `ChapterModule`, `ChapterController`, and `ChapterService` files are deleted
- [ ] Chapter, Translation, Page entities are moved to `backend/src/modules/manga/entities/`
- [ ] `MangaModule` imports `TypeOrmModule.forFeature([...moved entities])`
- [ ] All chapter-related endpoints and their tests are removed
- [ ] All existing tests still pass after the refactor
- [ ] No broken imports across the codebase

## Notes
- Check for any remaining references to the old module path before deleting files
- Ensure e2e tests and module imports in `AppModule` are updated
- The `chapter` database table name should remain unchanged (the entity class name change doesn't affect the table name unless explicitly configured)
