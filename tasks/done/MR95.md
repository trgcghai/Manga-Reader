# MR95: Create batch folder import hook with progress tracking

## Title

Create `useBatchImport` hook that handles sequential file upload + chapter creation with updatable toast progress.

## Description

The batch import flow iterates over files selected via a folder picker. Each file (CBZ/ZIP) is uploaded to MinIO via the existing `POST /files/upload/translation` endpoint, then a chapter is created via `POST /mangas/:mangaId/chapter`. Both steps must run sequentially per file to avoid overwhelming the server.

The hook encapsulates this loop with:
- A file parsing step that extracts the chapter number from the filename using a configurable regex
- Sequential execution: upload → chapter create → upload → chapter create → ...
- Updatable toast showing `2 / 15 chapters imported` with a progress bar
- The toast must survive navigation (implemented via `sonner` toast ID pattern — store the toast ID in a module-level variable so the same toast can be updated after navigation)

### Filename parsing (`parseChapterNumberFromFilename`)

A dedicated utility function `parseChapterNumberFromFilename(filename: string): number | null` extracts the chapter number from a filename. It must handle at minimum these cases (case-insensitive):

| Filename | Expected result |
|----------|----------------|
| `chapter 1.cbz` | `1` |
| `c002.zip` | `2` |
| `c200.4.cbz` | `200.4` |
| `chapter 100.1.zip` | `100.1` |
| `ChApTeR 5.cbz` | `5` (case-insensitive) |
| `readme.txt` | `null` (skip, not a chapter) |

#### Algorithm

1. Strip the file extension (everything after the last `.`)
2. Match against a pattern that looks for a known chapter prefix followed by a number:
   - Supported prefixes (case-insensitive): `chapter`, `ch`, `c`
   - Prefix may be followed by optional whitespace (` `, `_`, `-`) then a number
   - Number supports optional decimal part: `\d+(\.\d+)?`
3. If prefix-based match fails, fall back to a leading-number pattern: `^(\d+(?:\.\d+)?)` (catches filenames like `03-scan.cbz` → `3`)
4. If both fail, return `null`

#### Regex approach (single combined)

```
/^(?:chapter\s*|ch\s*|c\s*)?(\d+(?:\.\d+)?)/i
```

Testing against user examples:
- `chapter 1` → prefix `chapter` matches, `\s*` swallows the space, captures `1` ✓
- `c002` → prefix `c` matches, `\s*` matches zero whitespace, captures `002` → `parseFloat` → `2` ✓
- `c200.4` → prefix `c` matches, captures `200.4` ✓
- `chapter 100.1` → prefix `chapter` matches, captures `100.1` ✓

#### Integration

The `useBatchImport` hook calls this function per file. If it returns `null`, the file is skipped (toast warning: `"Skipped '{filename}' — could not determine chapter number"`). The parsed number is passed as `chapterNumber` to the upload endpoint.

### Flow per file

1. Call `uploadTranslation(file, mangaId, chapterNumber)` to upload the CBZ to MinIO
2. If upload fails → log error, mark file as failed, continue to next file
3. Call `createChapter(mangaId, { number, title, languageId, translatorId, url })` with the returned URL
4. If chapter create fails → log error, mark file as failed, continue
5. Update toast: `3 / 15 chapters imported`

### Aggregate result

After all files are processed, the toast updates to show final summary:
- `Successfully imported 12 / 15 chapters` on success
- `Imported 12 / 15 chapters (3 failed). Check console for details.` on partial failure

### Dependencies

- `useMutation` from `@tanstack/react-query` is used at the hook level for each per-file operation (or use raw fetch to avoid mutation state overhead)
- `toast` from `sonner` with persistent ID pattern
- Existing `uploadTranslation` from `#/services/api/fileApi`
- Existing `createChapter` from `#/services/api/mangaApi`

## Requirement

- Hook produces a single `mutate(files, options)` function that starts the import
- Tracks progress: total files, completed, failed
- Emits toast updates that survive page navigation
- Filename regex is configurable via parameter
- Each file's chapter number is extracted before upload
- Non-matching filenames are skipped with a warning
- Sequential execution (no concurrent uploads)
- Progress toast shows real-time count: "3 / 15 chapters imported"
- Final toast shows success/failure summary
- TypeScript strict; `cd frontend && npm run check` passes with 0 errors
