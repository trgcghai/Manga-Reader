# MR74: Add Prev/Next Chapter Navigation to Translation Detail Response

## Title

Include previous and next chapter translation references in the `GET /mangas/translations/:id` response.

## Description

The reader page currently loads a single translation with no knowledge of surrounding chapters. Users must navigate back to the manga detail page to switch chapters. The backend should return the previous and next chapter's best-matching translation alongside the current one, using a priority algorithm so the frontend can build prev/next chapter links.

### Algorithm for selecting adjacent chapter translation IDs

For each adjacent chapter (prev and next), query its translations and pick the first match in this priority order:

1. **Same translator + same language** — the translation whose `translator.id` and `language.id` both match the current translation
2. **Same language** — the first translation with the same `language.id` as the current translation
3. **Any translation** — fallback to any existing translation (first found)

If a chapter has no translations at all, the corresponding field is `null`.

### Performance note

Instead of loading all chapters of a manga (which could be hundreds), the repository queries are targeted:
- Find adjacent chapter: `WHERE mangaId = X AND number <|> currentNumber ORDER BY number DESC|ASC LIMIT 1` — constant time regardless of chapter count
- Load translations for that specific chapter: single `findOne` with relations — at most a handful of translations per chapter

Total: at most 2 extra SELECT queries (one per adjacent side), no full table scans.

### Changes needed

#### Backend

1. **Extend `TranslationDetailResponse`** with simple `prevTranslationId` / `nextTranslationId` fields:
   ```typescript
   prevTranslationId?: number | null;
   nextTranslationId?: number | null;
   ```
   No new DTO class needed — just the translation ID is enough.

2. **Add targeted repository methods**:
   - `ChapterRepository.findAdjacent(mangaId: number, currentNumber: number, direction: 'prev' | 'next'): Promise<Chapter | null>` — uses a single SQL query:
     - Prev: `WHERE mangaId = X AND number < currentNumber ORDER BY number DESC LIMIT 1`
     - Next: `WHERE mangaId = X AND number > currentNumber ORDER BY number ASC LIMIT 1`
   - `TranslationRepository.findByChapterId(chapterId: number): Promise<Translation[]>` — returns all translations for a chapter with `language` and `translator` relations loaded.

3. **Update `TranslationService.findOne()`**:
   - After loading the current translation, extract `chapter.manga.id` and `chapter.number`
   - For each direction (`'prev'` and `'next'`):
     - Call `chapterRepository.findAdjacent(mangaId, currentNumber, direction)`
     - If no adjacent chapter, skip (`null`)
     - Call `translationRepository.findByChapterId(adjChapter.id)`
     - Apply the 3-step priority algorithm against `currentTranslation.translator.id` and `currentTranslation.language.id`
     - Record `translation.id` as the result
   - Return `{ ..., prevTranslationId, nextTranslationId }` on the response

4. **Update tests** in `translation.service.spec.ts`:
   - Wire `mockChapterRepository` with `findAdjacent` method
   - Update existing `findOne` test to assert `prevTranslationId` and `nextTranslationId` when no adjacent chapters
   - Add new test cases for:
     - Adjacent chapter exists → picks same translator+language match
     - Adjacent chapter exists → falls back to same language match
     - Adjacent chapter exists → falls back to any translation
     - Adjacent chapter has no translations → returns `null`
     - Both prev and next chapters exist with valid translations

#### Frontend

5. **Add `prevTranslationId` and `nextTranslationId`** to `TranslationDetailResponse` type in `frontend/src/types/translation.ts`:
   ```typescript
   export interface TranslationDetailResponse {
     id: number;
     url: string;
     note?: string;
     createdAt: string;
     language: { id: number; code: string; name: string };
     translator: { id: number; name: string };
     chapter: {
       id: number;
       number: number;
       title?: string;
       manga: { id: number; title: string };
     };
     prevTranslationId?: number | null;
     nextTranslationId?: number | null;
   }
   ```

6. **No other frontend changes needed** — `getTranslation` already returns `TranslationDetailResponse` and will pick up the new fields automatically.
