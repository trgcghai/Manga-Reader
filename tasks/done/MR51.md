# MR51: Database Migration — Rename folderPath to url in Translation Table

## Title

Create a TypeORM migration to rename the `folderPath` column to `url` in the translation table, and update the entity file.

## Description

The `Translation` entity has a `folderPath` column that stores the URL/path to the translation's image pages. It should be renamed to `url` for clarity. The migration must be safe:
- Check if `folderPath` column exists before renaming (skip if already renamed)
- Check if `url` column already exists (skip if migration already ran)
- Preserve existing data during the rename

The current TypeORM setup uses `synchronize: true` in `app.module.ts` — this would drop and recreate the column, losing data. Instead, create a migration class with an `up` method that uses raw SQL to rename the column safely.

## Requirement

- Create `backend/src/modules/manga/migrations/RenameFolderPathToUrl.ts` with a migration class that:
  - On `up`: Rename `folderPath` to `url` in the `translation` table only if `folderPath` exists and `url` does not, using raw SQL
- Run the migration on startup in `main.ts` after the app is created but before `listen()`, using `DataSource.runMigrations()`
- Update `translation.entity.ts`: change `@Column() folderPath: string` to `@Column() url: string`
- Verify existing data is preserved after migration

## Acceptance Criteria

- [ ] Migration only runs if `folderPath` column exists and `url` column does not exist
- [ ] If `url` column already exists, migration is skipped (idempotent)
- [ ] Existing data in `folderPath` is preserved after rename to `url`
- [ ] Entity file column name matches the database column
- [ ] Migration runs automatically on startup
