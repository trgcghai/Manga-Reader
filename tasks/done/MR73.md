# MR73: Keyboard Navigation for Reader Page

## Title

Add keyboard navigation support to the page-mode reader.

## Description

The reader page (`PageViewer.tsx`) currently only supports mouse navigation — clicking the left third of the viewer goes to the previous page, and the right third goes to the next page. There is no keyboard support whatsoever. Users reading on a laptop or desktop expect to navigate pages using arrow keys and/or the spacebar without needing to reach for the mouse.

This task adds keyboard event handling so that `ArrowLeft` / `ArrowRight` (mapped to prev/next page) and the `Space` bar (mapped to next page) work anywhere on the reader page. In reading mode perspective, `ArrowLeft` means "previous page" and `ArrowRight` means "next page" by default (LTR convention). The keyboard listener should live at the reader page level (not inside `PageViewer` itself) to avoid focus-management issues with the image container.

## Requirement

- Add `ArrowLeft` → calls `prevPage()` (previous page)
- Add `ArrowRight` → calls `nextPage()` (next page)
- Add `Space` → calls `nextPage()` (next page)
- Keyboard events should be handled via a `useEffect` with `window.addEventListener('keydown', ...)` so they work regardless of focus state
- Prevent default browser scroll behavior for ArrowLeft/ArrowRight and Space when the reader is active
- Keyboard navigation must NOT interfere with text inputs or dialogs (exclude events when `event.target` is an `input`, `textarea`, `[contenteditable]`, or inside a dialog)
- Add unit tests for all keyboard shortcuts

## Acceptance Criteria

- [ ] Pressing `ArrowLeft` on the reader page navigates to the previous page
- [ ] Pressing `ArrowRight` navigates to the next page
- [ ] Pressing `Space` navigates to the next page
- [ ] Keyboard events are suppressed when focus is in an input, textarea, or contenteditable element
- [ ] Browser scroll is prevented for the handled keys (ArrowLeft, ArrowRight, Space) on the reader page
- [ ] Keyboard navigation works correctly in both single and double display modes
- [ ] Keyboard does nothing on first page (ArrowLeft/Space) or last page (ArrowRight)
- [ ] Unit tests cover each keybinding, boundary conditions (first/last page), and suppression inside input elements
- [ ] `cd frontend && npm run build` passes with 0 errors
- [ ] `cd frontend && npm run test` passes with 0 failures
- [ ] `cd frontend && npm run lint` passes with 0 errors
