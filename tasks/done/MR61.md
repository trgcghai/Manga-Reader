# MR61: Backend — Add GET /files/download Endpoint for File Download from Minio

## Title

Add `GET /files/download?url=` endpoint that streams a file from Minio by extracting the key from its URL, returning it as a downloadable attachment.

## Description

The `FileService` already has a `download(key)` method that fetches a file from Minio and returns a `StreamableFile`, but it's not exposed via any HTTP route. When the frontend (or any client) needs to download a CBZ translation file, it needs an endpoint that accepts the Minio URL (returned by the upload endpoints) and serves the file back as a download.

The flow:
1. Client sends `GET /files/download?url=http://minio:9000/bucket/manga/1/chapter/1/translations/uuid.cbz`
2. Controller extracts the Minio key from the URL using `extractKeyFromUrl`
3. Calls `fileService.download(key)` to get the file stream
4. Returns the stream with `Content-Disposition: attachment` and the correct `Content-Type`

### Changes needed

1. **FileController** — Add `@Get('download')` endpoint:
   - Accept `url` query param via `@Query('url')`
   - Extract key using `extractKeyFromUrl(url, fileService.endpoint, fileService.bucket)`
   - Return 400 if URL is invalid or key can't be extracted
   - Set `Content-Disposition` header dynamically with filename from the key
   - Call `fileService.download(key)` and return the `StreamableFile`

## Requirement

- Add `@Get('download')` to `FileController`
- Import `Get`, `Query`, `StreamableFile`, `Header` (or set header inline), `BadRequestException` from `@nestjs/common`
- Import `extractKeyFromUrl` from `src/common/utils/file-mime.util`
- Extract key from the `url` query parameter
- Validate: 400 BadRequest if `url` is missing or key extraction returns null
- Return `StreamableFile` from `fileService.download(key)`
- Set `Content-Disposition: attachment; filename="<filename>"` dynamically using the last segment of the key
- Set `Content-Type` based on the file (handled by `fileService.download` which uses `getContentType`)
- Add unit tests for the new endpoint

## Acceptance Criteria

- [ ] `GET /files/download?url=<minio-url>` returns the file as a download stream
- [ ] `GET /files/download` without `url` returns 400
- [ ] `GET /files/download?url=<invalid-url>` returns 400
- [ ] `GET /files/download?url=<non-existent-key>` returns 404 (handled by FileService)
- [ ] Response includes `Content-Disposition: attachment; filename="..."` header
- [ ] `cd backend && npx tsc --noEmit` passes
- [ ] `cd backend && npm test` passes (all tests green)
