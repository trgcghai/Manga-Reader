# MR60: Backend — Delete Cover File When Manga Is Deleted

## Title

Delete the manga's cover file from Minio when the manga record is deleted.

## Description

When a manga is deleted via `DELETE /mangas/:id`, the cover image stored in Minio is never removed — a resource leak. The `MangaService.delete` method already fetches the existing manga (with `coverPath`) and already has `FileService` injected (from MR56). Add cleanup logic: if the manga has a cover, extract the key and delete it before removing the record.

## Requirement

- In `MangaService.delete`, after finding the existing manga:
  - If `existing.coverPath` is non-empty, extract the key via `extractKeyFromUrl()` (same utility from MR56)
  - Call `fileService.delete(key)` if a valid key is extracted
  - Wrap in try/catch, log errors, continue with deletion

## Acceptance Criteria

- [ ] Deleting a manga with a cover removes the cover file from Minio
- [ ] Deleting a manga without a cover skips file deletion
- [ ] Delete failure does not block the manga deletion (logged, not thrown)
- [ ] `cd backend && npx tsc --noEmit` passes
- [ ] `cd backend && npm test` passes (all tests green)
