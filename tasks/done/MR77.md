# MR77: Wire ReaderSettingsSheet with Store

## Title

Redesign ReaderSettingsSheet with shadcn components and wire to Zustand reader store for display mode and reading mode settings.

## Description

The current `ReaderSettingsSheet` is a mock placeholder with hardcoded Tailwind color classes and non-functional controls. It needs to be:

1. **Redesigned with proper shadcn components** — replace raw `div` controls with `ToggleGroup` for Display Mode selection, use semantic CSS tokens (`bg-background`, `text-muted-foreground`) instead of raw `zinc-*` classes, and follow shadcn composition patterns (proper `Sheet` structure, `Separator` without manual overrides, `gap-*` instead of `space-y-*`).

2. **Wired to the Zustand reader store** — read `displayMode` and `readingMode` from `useReaderStore`, call `setDisplayMode`/`setReadingMode` when the user toggles a control. The store already has these actions defined (currently unused dead code).

### Current state

- `frontend/src/components/reader/ReaderSettingsSheet.tsx` — mock only, raw Tailwind colors, non-functional
- `frontend/src/stores/rootStore.ts` — has `displayMode` ('single'|'double'), `readingMode` ('page'|'scroll') with setters, but never called from anywhere
- `frontend/src/routes/_reader/reader.$translationId.tsx` — reads `displayMode` from store and passes to `PageViewer`, wraps UI in `ReaderSettingsSheet`

### Changes needed

#### 1. Redesign ReaderSettingsSheet

- Use `ToggleGroup` from `#/components/ui/toggle-group` (2 items: Single / Double for display mode, Page / Scroll for reading mode)
- Replace `bg-zinc-950`, `text-zinc-100`, `border-zinc-800` etc. with semantic tokens (`bg-background`, `text-foreground`, `text-muted-foreground`, `border-border`)
- Replace `space-y-*` with `flex flex-col gap-*`
- Replace manual `bg-zinc-800` on Separator with plain `<Separator />`
- Keep keyboard shortcuts section as reference (styled with shadcn patterns)
- SheetTrigger button: use `data-icon` pattern for the Settings icon
- SheetContent: no custom `bg-*` or `border-*` overrides

#### 2. Wire to Zustand store

- Import `useReaderStore` in `ReaderSettingsSheet.tsx`
- Read `displayMode` from store to set `ToggleGroup` value
- Read `readingMode` from store to set second `ToggleGroup` value
- Call `setDisplayMode`/`setReadingMode` on value change
- The store's `readingMode` will also need to affect `useReaderPages` or `PageViewer` in future (out of scope for this task — just wire the setting persistence)

#### 3. Remove dead store import from route

- After wiring, the route no longer needs to pass `displayMode` to `PageViewer` since the sheet reads directly from store
  - Actually, `PageViewer` still needs `displayMode` as a prop — the store reading stays in the route for now. Keep as-is.

## Requirement

- `ReaderSettingsSheet` uses shadcn `ToggleGroup` for Display Mode (Single/Double)
- `ReaderSettingsSheet` uses shadcn `ToggleGroup` for Reading Mode (Page/Scroll)
- No raw Tailwind color classes (`zinc-*`) on Sheet wrapper or controls — use semantic tokens
- `displayMode` changes persist to the store and affect `PageViewer` immediately
- `readingMode` changes persist to the store (UI wiring only, actual scroll behavior is future work)
- Reader trigger button uses `data-icon` on the Settings icon
- `cd frontend && npm run build` passes with 0 errors
- `cd frontend && npm run test` passes with 0 failures
