# MR81: Store scroll position & scroll-aware keyboard handler

## Title

Add `scrollPosition` to store and make `useReaderKeyboard` readingMode-aware.

## Description

The store already has a `readingMode` field (`'page' | 'scroll'`) with a setter, but nothing reads it. This task adds scroll position tracking to the store and makes the keyboard handler dispatch different actions depending on the current reading mode.

### Store changes

- Add `scrollPosition: number` (default `0`) and `setScrollPosition(n: number)` to `TranslationSlice`
- `scrollPosition` tracks the Y scroll offset of the scroll viewer in pixels
- `reset()` must reset `scrollPosition` to `0`

### Keyboard handler changes

Modify `useReaderKeyboard` to accept `readingMode` and optional scroll callbacks:

```typescript
interface UseReaderKeyboardOptions {
  onNextPage: () => void
  onPrevPage: () => void
  onScrollUp?: () => void
  onScrollDown?: () => void
  enabled: boolean
  readingMode: 'page' | 'scroll'
}
```

Key mappings by reading mode:

| Key | Page mode | Scroll mode |
|-----|-----------|-------------|
| `ArrowLeft` | `onPrevPage()` | `onPrevPage()` (chapter nav) |
| `ArrowRight` | `onNextPage()` | `onNextPage()` (chapter nav) |
| `ArrowUp` | — | `onScrollUp()` |
| `ArrowDown` | — | `onScrollDown()` |
| `PageUp` | — | `onScrollUp()` |
| `PageDown` | — | `onScrollDown()` |
| `Space` | `onNextPage()` | `onScrollDown()` |

- Tag suppression (INPUT, TEXTAREA, contentEditable) applies to all keys
- `onScrollUp`/`onScrollDown` are optional — the hook ignores them when undefined or when readingMode is `'page'`
- The `onNextPage`/`onPrevPage` dependency array and effect re-run when `readingMode` changes

## Requirement

- `scrollPosition` field and `setScrollPosition` action added to `TranslationSlice`
- `reset()` clears `scrollPosition`
- `useReaderKeyboard` accepts `readingMode` and optional `onScrollUp`/`onScrollDown`
- Key dispatch matches the table above based on `readingMode`
- Existing page-mode behavior is unchanged (backward compatible default `readingMode: 'page'`)
- `cd frontend && npm run build` passes with 0 errors

## Acceptance Criteria

- [ ] `scrollPosition` field exists on store with default `0`
- [ ] `setScrollPosition(n)` updates the field
- [ ] `reset()` sets `scrollPosition` back to `0`
- [ ] `useReaderKeyboard` interface includes `readingMode` and optional `onScrollUp`/`onScrollDown`
- [ ] Page mode: ArrowLeft/Right/Space behave exactly as before
- [ ] Scroll mode: ArrowUp/Down/PageUp/PageDown/Space trigger scroll callbacks (not page callbacks)
- [ ] Scroll mode: ArrowLeft/Right still trigger page callbacks (for chapter navigation)
- [ ] Scroll callbacks are ignored when readingMode is `'page'`
- [ ] Tag suppression works for all keys in both modes
- [ ] `cd frontend && npm run build` passes with 0 errors
