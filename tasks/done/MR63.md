# MR63: Backend — Add GET /translations/:id Endpoint for Single Translation

## Title

Add `GET /mangas/translations/:translationId` endpoint that returns a single translation with its chapter and manga context, needed by the reader page to load translation data by ID.

## Description

The reader page navigates to `/reader/$translationId` and needs to fetch the translation's CBZ URL along with its chapter and manga context. Currently there is no dedicated endpoint for a single translation — translations are only returned as part of the manga detail response (`GET /mangas/:id?include=chapters,translations`). A lightweight endpoint that returns just one translation is needed.

`TranslationRepository.findById()` already loads `chapter` and `chapter.manga` relations.

### Changes needed

1. **TranslationService** — Add `findOne(translationId: number)` method:
   - Call `translationRepo.findById(translationId)`
   - Throw `NotFoundException` if not found
   - Return translation data

2. **MangaController** — Add `@Get('translations/:translationId')` endpoint:
   - Accept `translationId` param (ParseIntPipe)
   - Call `translationService.findOne(translationId)`
   - Return the translation

## Requirement

- Add `findOne` method to `TranslationService`
- Add `GET /mangas/translations/:translationId` to `MangaController`
- Return the translation entity (TypeORM will serialize with eager relations: language, translator, chapter, chapter.manga)
- Return 404 if translation not found
- Add unit tests

## Acceptance Criteria

- [ ] `GET /mangas/translations/:translationId` returns the translation with language, translator, chapter, and chapter.manga
- [ ] Returns 404 for non-existent translation
- [ ] `cd backend && npx tsc --noEmit` passes
- [ ] `cd backend && npm test` passes (all tests green)
