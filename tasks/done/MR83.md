# MR83: Route integration & settings sheet navigation descriptions

## Title

Wire readingMode in the reader route and update settings sheet navigation hints.

## Description

The reader route (`reader.$translationId.tsx`) currently always renders `PageViewer`. It must conditionally render `ScrollViewer` when `readingMode === 'scroll'`. The settings sheet navigation section must show context-appropriate keyboard shortcuts depending on the current reading mode.

### Route changes

- Read `readingMode` from the store alongside `displayMode`
- Conditionally render `PageViewer` or `ScrollViewer`:

```tsx
{readingMode === 'scroll' ? (
  <ScrollViewer
    pages={pages}
    displayMode={displayMode}
    onPrevChapter={handlePrevPage}
    onNextChapter={handleNextPage}
  />
) : (
  <PageViewer
    pages={pages}
    displayMode={displayMode}
    currentPage={currentPage}
    onNextPage={handleNextPage}
    onPrevPage={handlePrevPage}
  />
)}
```

- Pass `readingMode` to `useReaderKeyboard`:

```tsx
useReaderKeyboard({
  onNextPage: handleNextPage,
  onPrevPage: handlePrevPage,
  enabled: pages.length > 0,
  readingMode,
})
```

- The existing `handleNextPage`/`handlePrevPage` callbacks remain unchanged — they handle chapter boundaries and are shared between PageViewer's page-next and ScrollViewer's chapter-next
- No changes needed to `pendingDirection` logic — it already handles chapter-to-chapter navigation on pages change

### Settings sheet changes

Update the Navigation section in `ReaderSettingsSheet` to show different content based on `readingMode`:

**Page mode:**
| Shortcut | Action |
|----------|--------|
| `→` / `Space` | Next Page |
| `←` | Prev Page |

**Scroll mode:**
| Shortcut | Action |
|----------|--------|
| `↑` / `PgUp` | Scroll Up |
| `↓` / `PgDn` / `Space` | Scroll Down |
| `←` | Prev Chapter |
| `→` | Next Chapter |

- The Command list should show only the relevant shortcuts for the current reading mode
- Use the same styling pattern as existing items (CommandItem with CommandShortcut, lucide icons)

## Requirement

- Route reads `readingMode` and renders `ScrollViewer` or `PageViewer` accordingly
- `useReaderKeyboard` receives `readingMode` prop
- Settings sheet navigation section shows page-mode or scroll-mode shortcuts based on `readingMode`
- Existing page-mode behavior is completely unchanged
- `cd frontend && npm run build` passes with 0 errors

## Acceptance Criteria

- [ ] Route reads `readingMode` from store

- [ ] `cd frontend && npm run build` passes with 0 errors
