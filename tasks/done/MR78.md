# MR78: Make Store Navigation displayMode-Aware

## Title

Make `nextPage()` / `prevPage()` advance by 2 when `displayMode` is `'double'`.

## Description

Currently `nextPage()` and `prevPage()` in `rootStore.ts` always advance `currentPage` by ±1 regardless of `displayMode`. In double-page mode, each spread covers two physical pages, so navigation should jump by 2 to skip to the next/previous spread. Without this fix, pressing next in double mode shows overlapping spreads (e.g., page 2 appears twice).

**File:** `frontend/src/stores/rootStore.ts:66-77`

### Current behavior:

```ts
nextPage: () =>
  set((state) => ({
    currentPage:
      state.totalPages === 0
        ? state.currentPage
        : Math.min(state.currentPage + 1, state.totalPages - 1),
  })),

prevPage: () =>
  set((state) => ({
    currentPage: Math.max(state.currentPage - 1, 0),
  })),
```

### Expected behavior:

- When `displayMode === 'double'`, advance by 2 instead of 1 (clamped to `totalPages - 1` for next, `0` for prev)
- When `displayMode === 'single'`, behavior stays the same (advance by 1)
- `nextPage` still clamps to `totalPages - 1` (in double mode, if only 1 page remains, `Math.min(current + 2, totalPages - 1)` correctly lands on the last single page)
- `prevPage` still clamps to `0`

## Requirement

- `nextPage()` advances `currentPage` by `displayMode === 'double' ? 2 : 1`
- `prevPage()` decreases `currentPage` by `displayMode === 'double' ? 2 : 1`
- Both clamp to valid range (`[0, totalPages - 1]`)
- Existing single-mode navigation is unchanged
- All existing tests pass; double-mode navigation tests added

## Acceptance Criteria

- [ ] In single mode: pressing next from page 0 → 1 (unchanged behavior)
- [ ] In double mode: pressing next from page 0 → 2 (skips to next spread)
- [ ] In double mode with 3 pages: pressing next from page 0 → 2 (last page alone), pressing next again stays at 2 (boundary clamped)
- [ ] In double mode: pressing prev from page 2 → 0 (skips back one spread)
- [ ] `npm run build` passes with 0 errors
- [ ] `npm run test` passes with 0 failures (all existing + new tests)

## Edge Cases

- **totalPages === 1**: step 1 or 2 both clamp to 0. Single page, no navigation needed.
- **totalPages === 2**: double mode from 0 → Math.min(2, 1) = 1 (last page). Correct — last page alone.
- **totalPages === 2**: single mode from 0 → 1. Correct.
- **currentPage at boundary**: double mode, 4 pages, at page 2 → Math.min(4, 3) = 3. Correct — shows last page alone if odd total. Actually with 4 pages (0,1,2,3): spread [3,4] starts at page 2, next → 4, clamped to 3. That's wrong! 4 pages → last spread is [3,4] at page 2. Next should go to boundary. 2+2=4, clamped to 3. But page 3 is the last page alone. Should it clamp to 2 instead? No — in double mode with even pages, every page is in a spread. The last spread [3,4] starts at page 2. Pressing next from page 2 should trigger chapter advance since there's no next spread. So the boundary logic in the route handles this — the store just clamps to valid range, and the route's `if (currentPage >= totalPages - step)` handles chapter advance.
