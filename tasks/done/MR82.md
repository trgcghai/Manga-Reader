# MR82: Scroll viewer component

## Title

Create `ScrollViewer` component that renders all pages in a scrollable container with single/double display mode support.

## Description

Currently `PageViewer` renders one page (or one spread) at a time with page-by-page navigation. Scroll mode requires a new component (`ScrollViewer`) that renders **all** pages vertically in a single scroll container, with the user scrolling continuously.

### ScrollViewer API

```typescript
interface ScrollViewerProps {
  pages: string[]
  displayMode: 'single' | 'double'
  onPrevChapter: () => void
  onNextChapter: () => void
}
```

No `currentPage` prop — the component derives the currently visible page from scroll position and syncs it to the store via `useReaderStore.getState().setCurrentPage()`.

### Rendering behavior

- Wrapper is a full-height scrollable container (`overflow-y-auto`, `h-full`)
- Pages are stacked vertically
- Single mode: each image is full-width, constrained by `max-w-full object-contain` (height auto)
- Double mode: pages are paired into spreads (0-1, 2-3, 4-5…). Each spread is a flex row with `max-h-screen max-w-[50vw]` per image, `gap-1`. The last spread with a single page renders the page centered at full width (like the solo-page fix in PageViewer)
- No fixed viewport height per image — images flow naturally with the document

### Scroll position tracking

- On scroll event, compute which page/spread is **closest to the top of the viewport** using `getBoundingClientRect` on a ref per page/spread
- Call `useReaderStore.getState().setCurrentPage()` with the 0-based index of the first page in the visible spread
- Use passive scroll listener for performance
- Throttle/debounce scroll handler (e.g., `requestAnimationFrame` throttling) to avoid excessive store updates

### Chapter boundary detection

- When the user scrolls to the **top** of the container (scrollTop ≈ 0) and tries to scroll further up, call `onPrevChapter()`
- When the user scrolls to the **bottom** (scrollTop + clientHeight >= scrollHeight) and tries to scroll further down, call `onNextChapter()`
- Use a small threshold (e.g., 1px) to avoid edge-case flickering

### Error handling

- Reuse the same per-image error handling pattern as PageViewer: `useState<Set<number>>`, onError replaces the image with a placeholder div
- Reset errored set when `pages` array changes

### PageIndicator

- Reuse the existing `PageIndicator` component — show it in the same absolute-bottom-center position
- The indicator updates as the user scrolls (driven by the `currentPage` from store)

### Image cleanup

- When the component unmounts or `pages` changes, no special cleanup needed since object URL management is handled by `useReaderPages`
