# MR59: Backend — Delete Translation File from Minio When URL Is Updated or Translation Is Deleted

## Title

Inject FileService into TranslationService and delete the translation file from Minio when the URL is changed (update) or when the translation record is deleted.

## Description

When a translation's URL is updated (user uploads a new CBZ file) or when a translation is deleted, the CBZ file remains in Minio forever — a resource leak. Both `TranslationService.update` and `TranslationService.delete` need to remove the file from Minio.

This mirrors the same pattern defined in MR56 for manga `coverPath`:
1. Inject `FileService`, `Logger`, and `extractKeyFromUrl` utility
2. In `update()`: if the URL is changing, delete the old file
3. In `delete()`: if the translation has a URL, delete the file before removing the record

## Requirement

- Inject `FileService` into `backend/src/modules/manga/services/translation.service.ts`
- In `update()`:
  - Read `translation.url` (the existing URL)
  - If `dto.url !== undefined` and existing URL is non-empty:
    - Extract key via `extractKeyFromUrl()` and call `fileService.delete(key)`
  - Wrap in try/catch, log on failure, continue with update
- In `delete()`:
  - Before calling `translationRepo.delete()`, if `translation.url` is non-empty:
    - Extract key via `extractKeyFromUrl()` and call `fileService.delete(key)`
  - Wrap in try/catch, log on failure, continue with deletion

## Acceptance Criteria

- [ ] `TranslationService.update` deletes the old file when a new URL is provided
- [ ] `TranslationService.update` does nothing when `url` is not provided (unchanged)
- [ ] `TranslationService.delete` deletes the file when translation has a URL
- [ ] `TranslationService.delete` does nothing when translation has no URL
- [ ] Delete failure does not block the update or deletion (logged, not thrown)
- [ ] `cd backend && npx tsc --noEmit` passes
- [ ] `cd backend && npm test` passes (all tests green)
