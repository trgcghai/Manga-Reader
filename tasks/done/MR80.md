# MR80: Fix Cross-Chapter Page Landing for Double Mode

## Title

Land reader on correct first/last spread when crossing chapter boundaries in double mode.

## Description

Two related fixes in `reader.$translationId.tsx`:

### 1. Boundary check (`handleNextPage`/`handlePrevPage`, lines 46-72)

The current check `if (currentPage < totalPages - 1)` always compares against the last physical page index. In double mode, the last complete spread starts at `totalPages - 2` (even-length chapter). After that spread, pressing next should immediately try the next chapter — no extra step for a half-spread ghost page.

**Fix:** read `displayMode` (already destructured on line 33) and use `const step = displayMode === 'double' ? 2 : 1` as the boundary offset:
- `handleNextPage`: `if (currentPage < totalPages - step)` → calls `nextPage()`, else tries chapter advance
- `handlePrevPage`: stays at `if (currentPage > 0)` — same as before (prev from any page past 0 should go back)

### 2. Landing on correct spread after boundary cross (lines 74-83)

The `pendingDirection` `useEffect` sets `currentPage` to `0` (next chapter) or `pages.length - 1` (prev chapter). In double mode, `pages.length - 1` may be a right-only solo page (odd-length chapter).

**Fix:** use the same `step` to calculate the last spread start:
- `displayMode === 'double'` && prev chapter → `setCurrentPage(Math.floor((pages.length - 1) / 2) * 2)`
- Otherwise → current logic (`0` for next, `pages.length - 1` for prev)

**File:** `frontend/src/routes/_reader/reader.$translationId.tsx:46-83`

## Requirement

- `handleNextPage` boundary check uses `displayMode` to determine step size (1 for single, 2 for double)
- `pendingDirection` `useEffect` accounts for `displayMode` when setting the landing page
- `displayMode` is already destructured from `useReaderStore()` in the route (no new import needed)
- Single-mode behavior is unchanged
