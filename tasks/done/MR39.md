# MR39: Create Chapter API

## Title
Implement create chapter endpoint under manga resource.

## Description
Add a `POST /manga/{mangaId}/chapter` endpoint that creates a new chapter belonging to a specific manga. The chapter is nested under the manga resource to reflect the parent-child relationship.

## Requirements
- Create a new endpoint: `POST /manga/:mangaId/chapter`
- The endpoint must be implemented in or wired through the Manga module (post-MR38 consolidation)
- Validates that the parent manga exists before creating the chapter
- Payload fields:

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `title` | string | yes | Chapter title |
| `releaseDate` | string (ISO date) | no | Release date |
| `note` | string | no | Optional note |
| `language` | number (Language ID) | yes | Reference to a Language entity |
| `translator` | number (Translator ID) | yes | Reference to a Translator entity |
| `folderPath` | string | yes | Path to chapter files on disk |

- Persist the chapter with a foreign key reference back to the parent manga
- Return the created chapter entity (including its id) with status 201
- Return 404 if the manga does not exist
- Return 400 for validation errors (missing required fields, invalid language/translator references)

## Acceptance Criteria
- [ ] `POST /manga/:mangaId/chapter` creates a chapter and returns 201
- [ ] Attempting to create a chapter for a non-existent manga returns 404
- [ ] Missing required fields return 400
- [ ] Invalid language or translator IDs return 400
- [ ] The chapter is persisted with a correct mangaId foreign key
- [ ] All existing tests still pass

## Notes
- A `CreateChapterDto` should validate the incoming payload
- Language and Translator existence should be verified before saving
- The endpoint should be placed in the Manga module (after MR38 consolidation moves chapter logic there)
- Consider adding an e2e test for the new endpoint
