# MR67: Frontend — Keyboard Navigation and Progress Persistence

## Title

Implement keyboard arrow key navigation for both page and scroll reading modes, plus save/restore reading progress to localStorage.

## Description

The reader needs keyboard controls for fluid navigation. Two reading modes have distinct keyboard behaviors. Reading progress (current chapter, current page) should persist so users can resume where they left off.

### Keyboard navigation rules

**Page mode:**
| Key | Action |
|---|---|
| ArrowLeft | Previous page (go to previous chapter's last page if on first page) |
| ArrowRight | Next page (go to next chapter's first page if on last page) |
| ArrowUp | Navigate to previous chapter (fetch its first translation) |
| ArrowDown | Navigate to next chapter (fetch its first translation) |

**Scroll mode:**
| Key | Action |
|---|---|
| ArrowUp | Scroll up by one viewport height |
| ArrowDown | Scroll down by one viewport height |
| ArrowLeft | Navigate to previous chapter |
| ArrowRight | Navigate to next chapter |

### Changes needed

1. **Chapter navigation context** — The reader route needs access to the manga's chapter list:
   - Fetch manga detail with chapters (from store's currentTranslation context) on mount
   - Store chapter list for prev/next chapter navigation

2. **Keyboard handler hook** — Create `frontend/src/hooks/useReaderKeyboard.ts`:
   - Accept callbacks: `onPrevPage`, `onNextPage`, `onPrevChapter`, `onNextChapter`, `onScrollUp`, `onScrollDown`
   - Attach `keydown` event listener on mount
   - Dispatch appropriate callback based on reading mode and key pressed
   - Detach listener on unmount
   - Handle edge cases: no prev/next chapter available, no prev/next page

3. **Page mode integration** — Wire keyboard into PageViewer:
   - ArrowLeft/Right call `prevPage()`/`nextPage()` from store
   - At boundaries, dispatch chapter change
   - Track current page in store

4. **Scroll mode integration** — Wire keyboard into reader:
   - ArrowUp/Down scroll the container smoothly
   - ArrowLeft/Right navigate chapters
   - Update store's `currentPage` based on scroll position (which image is most visible in viewport)

5. **Progress persistence** — Create `frontend/src/stores/persistence.ts`:
   - On page change or chapter change: save `{ translationId, page, chapterId, mangaId }` to localStorage key `reader-progress`
   - On reader mount: check localStorage for saved progress, restore if available
   - Debounce saves (500ms) to avoid excessive writes
   - Handle missing/corrupt localStorage data gracefully

6. **Chapter navigation UI** — Add minimal prev/next chapter buttons (visible on hover or always):
   - Overlay buttons on left/right edges of reader
   - Keyboard shortcuts as the primary interaction
   - Buttons as secondary/accessible fallback

## Requirement

- Create `useReaderKeyboard` hook with mode-aware key handling
- Implement chapter navigation (prev/next chapter by fetching from chapter list)
- Save reading progress to localStorage on page/chapter changes
- Restore progress on reader mount (scroll to saved page)
- Add overlay prev/next chapter buttons
- Handle edge cases: first/last page boundaries, first/last chapter boundaries
- `cd frontend && npm run build` passes with 0 errors

## Acceptance Criteria

- [ ] Page mode: Left/Right arrows turn pages
- [ ] Page mode: Up/Down arrows navigate to prev/next chapter
- [ ] Page mode: On first page, ArrowLeft goes to prev chapter's last page
- [ ] Page mode: On last page, ArrowRight goes to next chapter's first page
- [ ] Scroll mode: Up/Down scroll by viewport height
- [ ] Scroll mode: Left/Right navigate chapters
- [ ] Progress saved to localStorage on page/chapter change
- [ ] Progress restored on returning to reader (last read page)
- [ ] Chapter navigation buttons visible on hover
- [ ] `cd frontend && npm run build` passes with 0 errors
