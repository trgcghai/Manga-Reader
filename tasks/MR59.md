# MR59: Backend — Delete Old Translation File from Minio When Translation URL Is Updated

## Title

Inject FileService into TranslationService and delete the old translation file from Minio when a translation's URL is changed via the update endpoint.

## Description

When a translation's URL is updated (user uploads a new CBZ file), the old CBZ file remains in Minio forever. The `TranslationService.update` method needs to delete the previous file before overwriting the URL in the database.

This mirrors the same pattern defined in MR56 for manga `coverPath`:
1. Before updating the URL, read `existing.url`
2. If the old URL is non-empty and the new value is different, extract the Minio key from the old URL and call `FileService.delete(key)`
3. Log but don't throw on delete failure

No frontend changes are needed — the delete is triggered purely from the backend when the update request arrives.

## Requirement

- Inject `FileService` into `backend/src/modules/manga/services/translation.service.ts`
- In `update()`, before updating:
  - Read `translation.url` (the existing URL)
  - If `dto.url !== undefined` (caller explicitly set URL) and `existingUrl` is a non-empty string:
    - Extract key from the URL using the same `extractKeyFromUrl()` utility function or logic from MR56
    - Call `fileService.delete(key)`
  - Wrap delete call in try/catch, log the error on failure, and continue with the update
- Reuse `extractKeyFromUrl()` utility from MR56 (placed in `src/common/utils/file-mime.util.ts`)

## Acceptance Criteria

- [ ] `TranslationService.update` deletes the old file when a new URL is provided
- [ ] `TranslationService.update` does NOT delete anything when `url` is not provided (undefined — URL unchanged)
- [ ] Delete failure does not block the translation update (logged, not thrown)
- [ ] `cd backend && npx tsc --noEmit` passes with 0 errors
- [ ] `cd backend && npm test` passes (all tests green)
