# MR56: Backend — Delete Old Cover File from Minio When Manga coverPath Is Updated

## Title

Extract key from Minio URL, then call FileService.delete(key) to remove the old cover when manga coverPath changes.

## Description

When a manga's cover is updated via `PATCH /mangas/:id`, the frontend sends a new `coverPath` (a full Minio URL). The backend's `MangaService.update` method overwrites the database field but never deletes the old file from Minio — creating a resource leak.

The fix requires two changes in the backend:

1. **Utility function** — Create `extractKeyFromUrl(url: string): string | null` that parses a full Minio URL and extracts the object key. For example, from `http://localhost:9000/manga-pages/manga/cover/uuid.jpg` it extracts `manga/cover/uuid.jpg`. Place it in `backend/src/common/utils/file-mime.util.ts` or a new utility file.

2. **MangaService.update** — Inject `FileService`, and before overwriting `coverPath`:
   - If the old `coverPath` is non-empty and the new value is different (including removal to `''`), extract the key via `extractKeyFromUrl()` and call `fileService.delete(key)` to remove the orphaned file
   - Log but don't throw on delete failure (the DB update should succeed regardless)

No frontend changes are needed — the delete is triggered purely from the backend when the update request arrives.

## Requirement

- Add `extractKeyFromUrl(url: string, endpoint: string, bucket: string): string | null` to `backend/src/common/utils/file-mime.util.ts`
  - Extracts the key by stripping `${endpoint}/${bucket}/` from the URL start
  - Returns `null` if the URL doesn't match the expected format (not our Minio URL)
- Inject `FileService` into `backend/src/modules/manga/services/manga.service.ts`
- In `update()`, before updating:
  - Read `existing.coverPath`
  - If `dto.coverPath !== undefined` and `existing.coverPath` is a non-empty string:
    - Extract key via `extractKeyFromUrl(existing.coverPath, endpoint, bucket)`
    - If key is non-null, call `fileService.delete(key)`
- Wrap delete call in try/catch, log the error on failure, and continue with the update
- `FileService` must expose `endpoint` and `bucket` (or add getters) so `MangaService` can pass them to `extractKeyFromUrl`

## Acceptance Criteria

- [ ] `extractKeyFromUrl()` correctly extracts the key from `${endpoint}/${bucket}/` prefixed URLs
- [ ] `extractKeyFromUrl()` returns `null` for URLs not matching the expected format
- [ ] `MangaService.update` deletes the old cover when a new coverPath URL is provided
- [ ] `MangaService.update` deletes the old cover when coverPath is set to `''` (cover removed)
- [ ] `MangaService.update` does NOT delete anything when `coverPath` is not provided (undefined — cover unchanged)
- [ ] Delete failure does not block the manga update (logged, not thrown)
- [ ] `cd backend && npx tsc --noEmit` passes with 0 errors
- [ ] `cd backend && npm test` passes (all tests green)
