# MR85: Reading session persistence and restoration

## Title

Persist full reading session so users return to the exact chapter after page reload.

## Description

After MR84 adds the `persist` middleware infrastructure, the store currently saves only scalar values (page, mode, scroll position). It does not persist the active translation/chapter context, so after a page reload the reader shows a blank state — the user sees the manga list or an empty reader instead of resuming where they left off.

This task extends the persisted state to include `currentTranslation` and `currentChapter`, then handles restoration on app load:

### What to persist additionally

| Field | Reason |
|-------|--------|
| `currentTranslation` | Full translation response — restore the reading session verbatim |
| `currentChapter` | Chapter metadata — used for display (title, number, manga title) |

### Restoration flow

1. On page load, `persist` rehydrates the full store from `localStorage`
2. The route component checks if `currentTranslation` is non-null after rehydrate
3. If present, the route navigates to `reader/{translationId}` automatically
4. The reader renders with the correct chapter, page, and scroll position
5. A sonner `toast.info` displays the chapter title (e.g., "Resumed: Chapter 5 — The Beginning")

### Serialization concerns

`TranslationDetailResponse` contains nested objects (`language`, `translator`, `chapter.manga`) and ISO date strings. Zustand's `persist` serializes via `JSON.stringify`/`JSON.parse` by default, which handles these types correctly. No custom serializer is needed.

### Staleness

Since the app is local-only and manga files are static, translation data does not change between sessions. If the local library is rebuilt (rescan), translation IDs remain stable as long as files are unchanged. No explicit cache invalidation is required for v1.

## Requirement

- Full reading session persists across page reloads
- User lands on the same chapter and page after refresh
- A toast shows the resumed chapter title
- If persisted data is corrupted or stale, fall back to manga list gracefully
- `cd frontend && npm run build` passes with 0 errors

## Acceptance Criteria

- [ ] `currentTranslation` and `currentChapter` are added to the persist `partialize` whitelist
- [ ] After page reload while reading a chapter, the reader opens to the same chapter
- [ ] `currentPage` and `scrollPosition` are restored alongside the translation
- [ ] A toast notification shows the chapter title on resume (e.g., via `toast.info`)
- [ ] If `currentTranslation` is null after rehydrate (first visit or cleared), the app shows the manga list as normal (no crash)
- [ ] If the persisted translation ID no longer exists (library rescanned), the app gracefully shows the manga list instead of a blank/broken reader
- [ ] `cd frontend && npm run build` passes with 0 errors
