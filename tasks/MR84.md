# MR84: Zustand store persist middleware

## Title

Add persist middleware to Zustand store for cross-session state survival.

## Description

The Zustand reader store (`frontend/src/stores/rootStore.ts`) currently loses all state on page refresh — preferences (`readingMode`, `displayMode`), scroll position, and current page are all reset to defaults. Add `zustand/middleware`'s `persist` to automatically serialize selected store fields to `localStorage` and rehydrate on load.

The app runs inside TanStack Start (SSR), so the persistence layer must gracefully handle environments where `localStorage` is unavailable (server-side render, or if the storage API throws). Use a custom storage adapter that catches errors and falls back to in-memory.

### What to persist

| Field | Reason |
|-------|--------|
| `readingMode` | User preference — restore reading mode between sessions |
| `displayMode` | User preference — restore display mode between sessions |
| `currentPage` | Reading progress — restore last page on chapter reload |
| `totalPages` | Needed alongside currentPage for display consistency |
| `scrollPosition` | Scroll mode position — restore vertical scroll offset |

### What NOT to persist (initially)

- `currentTranslation` — large nested API response object; serialization/deserialization is error-prone (Date strings, nested relations). This will be handled in a follow-up task if needed.
- `currentChapter` — derived from `currentTranslation`; excluded for same reason.

### Implementation details

- Use `persist` from `zustand/middleware` (bundled with zustand 5.x — no install needed)
- Storage key: `manga-reader-store`
- `partialize` option to whitelist persisted fields
- Custom `storage` object that wraps `localStorage` with try/catch for SSR
- `version` field set to `1` for future schema migrations

## Requirement

- Store state survives full page reload
- `readingMode`, `displayMode`, `currentPage` are restored on rehydrate
- Scroll position is restored for scroll mode
- No errors or warnings in SSR/server context
- `cd frontend && npm run build` passes with 0 errors

## Acceptance Criteria

- [ ] `persist` middleware wraps the store creator in `rootStore.ts`
- [ ] Storage key `manga-reader-store` is used with `localStorage`
- [ ] SSR-safe storage adapter catches `localStorage` errors gracefully
