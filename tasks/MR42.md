# MR42: Chapter & Translation Creation Frontend

## Title
Admin chapter creation UI with form for chapter metadata and translation assignment.

## Description
Build the frontend UI for creating chapters and their translations for a manga. The backend endpoint `POST /mangas/{mangaId}/chapter` (from MR39) already exists and accepts `CreateChapterDto` (number, title, releaseDate, note, languageId, translatorId, folderPath). Currently there is no frontend form, page, or dialog that calls this API — the "Add Chapter" button on the detail page is a dead link to the manga edit page.

## Requirements

### Chapter Form
- A form to create a new chapter for a manga with the following fields:
  - **Chapter Number** (required, number input with min 0)
  - **Title** (required, text input)
  - **Release Date** (optional, date picker)
  - **Note** (optional, textarea)
  - **Language** (required, select dropdown populated from `GET /language`)
  - **Translator** (required, select dropdown populated from `GET /translators`)
  - **Folder Path** (required, text input, e.g. `/chapters/volume-1/chapter-1`)

### Entry Points
- Replace the "Add Chapter" button on the manga detail page (`$id.index.tsx`) so it opens the creation form instead of linking to the manga edit page
- Add a create button or link accessible from the manga detail page

### Interaction & States
- **Loading**: Disabled button state while submitting
- **Validation**: Inline validation for required fields before submission
- **Success**: Chapter created → close form → refetch manga detail to show new chapter in the list; show success toast
- **Error**: Show server error (e.g., duplicate chapter, invalid language/translator) as an alert or inline error

### Delivery Mechanisms
The form can be delivered as either:
- A dialog/modal that opens on the detail page (preferred — keeps user on the detail page)
- A dedicated route (e.g., `/admin/mangas/{id}/chapters/new`) — acceptable if dialog approach proves complex

### Relation to Translations
The `CreateChapterDto` includes both chapter-level fields and the translation-level fields (languageId, translatorId, folderPath). The backend creates or reuses the chapter and creates the translation in a single request. The form should reflect this combined structure — the user fills in chapter info AND picks language/translator/folder path together.

## Acceptance Criteria
- [ ] User can create a new chapter with all required fields from the manga detail page
- [ ] Language dropdown is populated from the backend (`GET /language`)
- [ ] Translator dropdown is populated from the backend (`GET /translators`)
- [ ] Form validates required fields before submission
- [ ] Successful creation closes the form, refetches manga detail, and shows the new chapter in the list
- [ ] Server errors (duplicate chapter, invalid language/translator) are shown to the user
- [ ] Loading/disabled state on the submit button while creating
- [ ] "Add Chapter" button on the detail page is wired to this creation flow
- [ ] No regressions to existing manga detail page, list, or other admin pages

## Notes
- Reuse existing `getLanguages()` from `languageApi.ts` and `getTranslators()` from `translatorApi.ts` for dropdown data
- Create a new `createChapter` API function in `mangaApi.ts` (or a new `chapterApi.ts`)
- Create a new `useCreateChapter` hook in `useManga.ts` (or a new `useChapter.ts`)
- The form can be a reusable component (`ChapterForm.tsx`) or inline in a dialog
- Follow existing form patterns (see `AuthorForm` or `MangaForm` patterns)
- The backend endpoint is `POST /mangas/:mangaId/chapter` with `CreateChapterDto` body
