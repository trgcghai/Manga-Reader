# MR52: Backend — Rename folderPath to url in DTOs, Services, and Specs

## Title

Update all backend TypeScript files to use `url` instead of `folderPath` for the Translation entity field.

## Description

After MR51 renames the database column from `folderPath` to `url`, all backend code referencing the old field name must be updated for consistency. This includes DTOs, services, and test files.

## Requirement

- Update `translation.dto.ts`: rename `folderPath` property to `url` in `UpdateTranslationDto`
- Update `chapter.dto.ts`: rename `folderPath` property to `url` in `CreateChapterDto`
- Update `manga.dto.ts`: rename `folderPath` to `url` in `ChapterTranslationResponse`
- Update `chapter.service.ts`: rename `dto.folderPath` to `dto.url` in both `translationRepo.create` calls (lines 58 and 74)
- Update `translation.service.ts`: rename `dto.folderPath` to `dto.url` in the update partial (line 46–48)
- Update `manga.service.ts`: rename `tr.folderPath` to `tr.url` in the response mapper (line 96)
- Update all spec/test files that reference `folderPath`:
  - `manga.controller.spec.ts`
  - `manga.repository.spec.ts`
  - `translation.repository.spec.ts`
  - `chapter.service.spec.ts`
  - `manga.service.spec.ts`
  - `translation.service.spec.ts`

## Acceptance Criteria

- [ ] All backend DTO properties renamed from `folderPath` to `url`
- [ ] All service code using the field updated to reference `url`
- [ ] All test files updated
- [ ] Full test suite passes (`cd backend && npm test`)
- [ ] TypeScript compiles with no errors (`cd backend && npx tsc --noEmit`)
