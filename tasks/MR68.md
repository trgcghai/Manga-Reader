# MR68: Frontend — Reading Progress Persistence

## Title

Save and restore reading progress (current chapter and page) to localStorage so users can resume where they left off.

## Description

Reading progress (current translation ID, page number) should persist across sessions. When a user returns to a previously opened translation, the reader should restore their last page. Progress saves are debounced to avoid excessive localStorage writes.

### Existing context

- `frontend/src/stores/rootStore.ts` exports `useReaderStore` (zustand) with:
  - State: `currentTranslation: TranslationDetailResponse | null`, `currentChapter: { id, number, title?, mangaId, mangaTitle } | null`, `currentPage: number`, `totalPages: number`, `readingMode: 'page' | 'scroll'`, `displayMode: 'single' | 'double'`
  - Actions: `setCurrentTranslation(t)`, `setCurrentPage(n)`, `setTotalPages(n)`, `nextPage()`, `prevPage()`, `reset()`
- `frontend/src/types/translation.ts` defines `TranslationDetailResponse` with `id: number`, `chapter: { id, number, manga: { id, title } }`
- `frontend/src/routes/_reader/reader.$translationId.tsx` is the reader page, uses `useParams` to get `translationId`
- Import alias `#/` maps to `frontend/src/`
- `useReaderKeyboard` (MR67) is already wired into the reader route
- `useDebounce` already exists at `frontend/src/hooks/useDebounce.ts` (check its signature)

### Changes needed

1. **Create persistence store** — `frontend/src/stores/persistence.ts`:
   - Define the saved shape:
     ```ts
     interface ReaderProgress {
       translationId: number
       page: number
       chapterId: number
       mangaId: number
     }
     ```
   - `STORAGE_KEY = 'reader-progress'`
   - `saveProgress(progress: ReaderProgress): void`:
     - `try { localStorage.setItem(STORAGE_KEY, JSON.stringify(progress)) } catch (e) { console.warn('Failed to save reader progress:', e) }`
     - Handle `QuotaExceededError` and other localStorage failures gracefully (just warn, don't throw)
   - `loadProgress(): ReaderProgress | null`:
     - `try { const raw = localStorage.getItem(STORAGE_KEY); if (!raw) return null; const parsed = JSON.parse(raw); return isValidProgress(parsed) ? parsed : null } catch { return null }`
   - `clearProgress(): void`:
     - `try { localStorage.removeItem(STORAGE_KEY) } catch { /* ignore */ }`
   - `isValidProgress(value: unknown): value is ReaderProgress`:
     - Check `value !== null && typeof value === 'object'`
     - Check `'translationId' in value && typeof value.translationId === 'number'`
     - Check `'page' in value && typeof value.page === 'number'`
     - Check `'chapterId' in value && typeof value.chapterId === 'number'`
     - Check `'mangaId' in value && typeof value.mangaId === 'number'`
     - Return `true` only if all checks pass

2. **Create progress persistence hook** — `frontend/src/hooks/useProgressPersistence.ts`:
   - Signature: `export function useProgressPersistence(options: { translationId: number }): void`
   - Internal implementation:
     - Subscribe to store: `const currentPage = useReaderStore(s => s.currentPage)`, `const currentChapter = useReaderStore(s => s.currentChapter)`, `const currentTranslation = useReaderStore(s => s.currentTranslation)`
     - On mount (`useEffect` with `[translationId]` dependency):
       - Call `loadProgress()`
       - If progress exists and `progress.translationId === translationId`:
         - Call `useReaderStore.getState().setCurrentPage(progress.page)`
       - Note: do NOT auto-navigate to a different chapter — only restore page position within the same translation
     - On change (`useEffect` watching `currentPage`, `currentTranslation?.id`, `currentChapter?.id`, `currentChapter?.mangaId`):
       - Skip save if `currentTranslation === null`
       - Build progress object: `{ translationId: currentTranslation.id, page: currentPage, chapterId: currentChapter.id, mangaId: currentChapter.mangaId }`
       - Debounce save by 500ms: use `setTimeout`/`clearTimeout` pattern (or reuse `useDebounce` from `#/hooks/useDebounce` if it fits)
       - Save via `saveProgress(progress)`
       - Cleanup timeout on unmount or dependency change
     - On unmount: flush the current state one final time (clear any pending timeout and save immediately)

3. **Integrate into reader route** — `frontend/src/routes/_reader/reader.$translationId.tsx`:
   - Import `useProgressPersistence` from `#/hooks/useProgressPersistence`
   - Call `useProgressPersistence({ translationId: Number(translationId) })` somewhere in the `ReaderPage` component
   - This hook should run regardless of loading state — it will only save once the store is populated
   - Ensure progress is restored before the PageViewer renders (the effect runs on mount and sets `currentPage` synchronously in the same render cycle)

## Requirement

- Create `frontend/src/stores/persistence.ts` with `saveProgress`, `loadProgress`, `clearProgress`, and `isValidProgress`
- Create `frontend/src/hooks/useProgressPersistence.ts` with debounced save (500ms) on store changes
- Restore saved page on mount only if the `translationId` matches the current route param
- Handle corrupt `localStorage` data gracefully (return `null`, don't crash)
- Clear pending save timeout and flush on unmount
- `cd frontend && npm run build` passes with 0 errors

## Acceptance Criteria

- [ ] `saveProgress(ReaderProgress)` writes JSON to `localStorage` under `reader-progress`
- [ ] `loadProgress()` returns `ReaderProgress | null`, handles corrupt data gracefully
- [ ] `clearProgress()` removes `reader-progress` from `localStorage`
- [ ] Progress saved on page change (`currentPage` changes in store) — debounced 500ms
- [ ] Progress saved on translation/chapter change
- [ ] Progress restored on reader mount: `setCurrentPage(savedPage)` when `translationId` matches
- [ ] Progress NOT restored if saved `translationId` differs from current route (no auto-navigation)
- [ ] On unmount: pending save is flushed immediately
- [ ] `localStorage` write failures are caught and logged as warnings, not thrown
- [ ] `cd frontend && npm run build` passes with 0 errors
