# MR76: Chapter Boundary Navigation

## Title

Handle chapter boundary navigation when pressing keyboard shortcuts or clicking page edges on first/last page.

## Description

Currently, pressing ArrowLeft/Space on the first page or ArrowRight on the last page (or clicking the left/right tap zones of PageViewer) does nothing — the store clamps to bounds silently. Instead, when at a chapter boundary, navigation should cross to the adjacent chapter's translation:

- **First page** (`currentPage === 0`) + ArrowLeft/Space or click-left → navigate to the previous chapter's translation
- **Last page** (`currentPage >= totalPages - 1`) + ArrowRight/Space or click-right → navigate to the next chapter's translation
- **No adjacent chapter** (via `prevTranslationId`/`nextTranslationId` from MR74) → show a toast: "This is the first chapter" / "This is the latest chapter"

### Design Decision

All boundary logic lives in route-level wrapper functions (`handleNextPage`/`handlePrevPage` in `reader.$translationId.tsx`). Both `PageViewer` and `useReaderKeyboard` receive the same wrappers. No changes to either component.

### Changes needed

#### 1. Route-level callback wrappers

In `reader.$translationId.tsx`:

- Import `useNavigate` from `@tanstack/react-router`
- Import `useCallback` from `react`
- Import `toast` from `sonner`
- Create `handleNextPage` with `useCallback`:
  - If `currentPage < totalPages - 1` → call `store.nextPage()`
  - Else if `data.nextTranslationId != null` → `navigate({ to: '/reader/$translationId', params: { translationId: String(data.nextTranslationId) } })`
  - Else → `toast.info('This is the latest chapter')`
- Create `handlePrevPage` with `useCallback`:
  - If `currentPage > 0` → call `store.prevPage()`
  - Else if `data.prevTranslationId != null` → `navigate(...)` (analogous)
  - Else → `toast.info('This is the first chapter')`
- Pass both wrappers to `PageViewer` (replacing raw `nextPage`/`prevPage`)
- Pass both wrappers to `useReaderKeyboard` (replacing raw `nextPage`/`prevPage`)

#### 2. No changes to `useReaderKeyboard` or `PageViewer`

The hook and component interfaces are unchanged. They just call whatever `onNextPage`/`onPrevPage` they receive.

## Acceptance Criteria

- [ ] First page + ArrowLeft → navigates to prev chapter or shows toast
- [ ] Last page + ArrowRight → navigates to next chapter or shows toast
- [ ] Last page + Space → navigates to next chapter or shows toast
- [ ] Middle page + ArrowLeft/ArrowRight/Space → normal page navigation
- [ ] PageViewer click-left on first page → same as ArrowLeft
- [ ] PageViewer click-right on last page → same as ArrowRight
- [ ] Single-page chapter (totalPages=1): ArrowLeft → prev chapter, ArrowRight → next chapter
- [ ] `npm run build` passes with 0 errors
- [ ] `npm run test` passes with 0 failures
